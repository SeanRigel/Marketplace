First, the thing that stops this recurring

Why any of this is in a terminal — and how to mostly stop

Two separate jobs have been tangled together. Pushing means sending code to GitHub. Deploying means putting the site on the internet. Neither has to be typed, and after step 4 below, deploying happens by itself every time you push.

  • GitHub Desktop (desktop.github.com) turns pushing into two button clicks. Worth installing once you're through this list.
  • Cloudflare's Git integration makes deploying automatic. Set up once in step 4; after that you never deploy manually again.
  • The only genuinely terminal-only piece is applying my patch — and that exists only because Claude has read-only access to your repo. Grant write access and even that disappears.
1

Install Node

5 min · no terminal

Needed to run the test suite and, this once, to deploy. It's a normal Mac installer — nothing to configure.

  1. Go to nodejs.org
  2. Download the macOS Installer (.pkg), LTS version
  3. Double-click it. Next, next, done.
Terminal — check it worked
$ node --version
Expect: a version number like v22.x.x. If it says "command not found", close Terminal completely and reopen it.
2

Apply my six commits and push

5 min · terminal

Download forkable-launch-build.patch from our chat first — it goes to your Downloads folder. Then open Terminal (⌘ Space, type "Terminal", Enter) and run these one line at a time, waiting for each to finish.

Terminal
$ cd ~/Marketplace
$ git pull origin main
$ git am ~/Downloads/forkablelaunchbuild.patch
$ ./scripts/test.sh
$ git push origin main
Expect: the test step ends with All checks passed, and the push ends with something like main -> main.
The filename may differ. Your browser strips hyphens — last time forkable-security-fixes.patch arrived as forkablesecurityfixes.patch. Check with ls ~/Downloads, or type git am and then drag the file from Finder into the Terminal window — it fills in the exact path for you.
If it asks for a password, that's the ghp_ token again, not your GitHub password. If you've lost it, make a new one at github.com/settings/tokens/new with the repo box ticked.
3

Make yourself an admin

2 min · browser only

The moderation system is already installed in your database. Nobody is an administrator yet, deliberately — there's no "first user wins" rule, because that's a race you could lose to a stranger who signs up before you do.

  1. Open supabase.com/dashboard → the Forkable project
  2. Left sidebar → SQL Editor → New query
  3. Paste this, with your own email, and click Run:
Supabase SQL Editor
update public.profiles set is_admin = true
where id = (select id from auth.users
            where email = 'you@example.com');
You need an account on the site first. If you've never signed up on your own app, this updates nothing. Deploy first (step 4), sign up, then come back.
4

Deploy — and make it automatic forever

15 min · mostly browser

Do it this way rather than with wrangler. It takes five minutes longer once, and then every future push deploys itself with no terminal at all.

  1. Go to dash.cloudflare.com and sign up if you haven't
  2. Left sidebar → Workers & Pages → Create → Pages tab → Connect to Git
  3. Authorise GitHub, then pick SeanRigel/Marketplace
  4. On the build settings screen:
    • Framework preset: None
    • Build command: leave completely empty
    • Build output directory: /
  5. Click Save and Deploy
Leave the build command empty. This project has no build step by design — that's a deliberate architectural rule, not an oversight. Anything in that box will fail the deploy.
Expect: a live URL like marketplace-abc.pages.dev. Open it on your phone. Sign up on the waitlist. Then check the waitlist table in Supabase — the row should be there. That's the one test I've never been able to run.
5

Buy a domain and a real support inbox

15 min · browser

Your Terms of Service and Privacy Policy both promise support@forkable.dev. That inbox doesn't exist. Published terms pointing at a dead mailbox are worse than no terms at all — so this one isn't cosmetic.

  1. Buy the domain. Cloudflare Registrar sells at cost and it's already where your site lives
  2. In Cloudflare Pages → your project → Custom domains → add it
  3. Set up email forwarding so support@ reaches your real inbox — Cloudflare Email Routing does this free

If you'd rather use a different address, tell me and I'll change it everywhere in the code instead.

6

Turn on analytics before traffic arrives

5 min · browser + one edit

Analytics can't be applied retroactively. Every visitor before you switch this on is invisible forever — including whether they clicked into a demo, which is the one number this whole product rests on.

  1. Cloudflare dashboard → Analytics & Logs → Web Analytics → Add a site
  2. Copy the token it gives you
  3. Open config.js in your repo, find analyticsToken: '', and paste the token between the quotes
  4. Commit and push — with step 4 done, that deploys itself

Cloudflare's version sets no cookies and needs no consent banner, which is why the privacy policy can say plainly that we run no advertising trackers.

7

Switch email on

10 min · browser

Receipts, sale alerts, refund confirmations and demo-down warnings are all built and tested — but they send nothing until there's a key. Right now a seller makes a sale and is never told.

  1. Sign up at resend.com (free tier: 3,000 emails a month)
  2. Verify the domain you bought in step 5
  3. Create an API key — it starts re_
  4. In Cloudflare Pages → your project → Settings → Environment variables, add three:
    • RESEND_API_KEY
    • MAIL_FROM — e.g. Forkable <hello@yourdomain.com>
    • SUPPORT_EMAIL — where replies land
  5. Redeploy. Environment variables don't apply to a deploy that already happened
